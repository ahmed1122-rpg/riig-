# MotionPrep Engineering Constitution

هذه القواعد ملزمة لتقليل تشتت الكود ومنع انحراف السلوك عن خريطة المنتج.

## 1. مصدر الحقيقة

- `packages/contracts` للعقود المشتركة فقط.
- `docs/BUILD_MAP.md` لقواعد المنتج والنطاق.
- API هو صاحب القرار في الصلاحيات والحصص والحالات؛ الواجهة لا تُعد طبقة أمان.
- PostgreSQL سيكون مصدر الحقيقة الإنتاجي؛ الذاكرة للاختبارات والـdemo فقط.

## 2. حدود الوحدات

- `apps/web` لا يستورد من `apps/api`.
- `apps/api` لا يستورد من `apps/web`.
- `packages/*` لا تستورد من `apps/*`.
- Routes تتحقق من المدخل وتفوض إلى Service؛ لا تحتوي منطق أعمال أو تنشئ Repository.
- Service يطبق الحالة والسياسة، وRepository يعزل التخزين.
- Admin يجمع قراءات من وحدات أخرى عبر عقودها، ولا يكتب في جداولها مباشرة.

## 3. الثوابت

- ملف واحد لكل رفع: سقف 30 MiB للصور وملفات PDF.
- الصور 15 طبقة كحد أقصى؛ PDF بلا حد طبقات.
- أسماء الطبقات تبدأ بـ`+` واحدة.
- كل Mutation قابل للتكرار يستخدم Idempotency key.
- كل إجراء إداري حساس يحتاج Actor وReason وAudit event.
- الدفع لا يثق في نتيجة المتصفح؛ Webhook موثق من المزود هو مصدر الحقيقة في Live.

## 4. بوابات الجودة

```text
architecture → typecheck → unit/integration → build → security → e2e/golden
```

الأمر `npm run verify:architecture` يفشل عند خرق اتجاهات الاستيراد الأساسية.

## 5. سياسة التغيير

- تغيير الحالات أو الصيغ أو الأدوار يبدأ من `packages/contracts`.
- تغيير قاعدة منتج يحدّث الخريطة والاختبار في نفس التغيير.
- لا يضاف مزود دفع داخل Routes؛ ينفذ `PaymentProvider`.
- لا تُعرض ميزة Live في الواجهة ما لم توجد مفاتيح Sandbox، تحقق Webhook، واختبارات.
