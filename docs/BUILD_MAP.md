# MotionPrep Studio — خريطة البناء والتنفيذ v6

هذه الوثيقة هي المرجع الوحيد الحالي لبنية المنتج وحالة التنفيذ. حُذفت الخرائط
القديمة لتفادي تعارض المسارات والوعود مع الكود.

## 1. الهدف والافتراضات

المنتج يقلل وقت تجهيز الصور والكتب للتحريك عبر مسار واحد:

`رفع مصدر → تجهيز تلقائي → تصحيح موجّه → مراجعة الطبقات → تصدير`

الافتراضات الحالية:

- فريق منتج صغير؛ البنية **Modular Monolith** مع عمال مستقلين، وليست
  Microservices مبكرة.
- PostgreSQL هو مصدر الحقيقة للحالات والبيانات الوصفية، وS3-compatible هو
  مصدر بايتات المصادر والأصول المسجلة في PostgreSQL. Redis طبقة تشغيلية
  مشتركة للـrate limiting وليست مخزن جلسات أو مصدر حقيقة؛ يجب أن يبقى فقدها
  المؤقت غير قادر على تغيير مستند طبقات أو استحقاق أو جلسة محفوظة.
- العربية وRTL هي الحالة الأساسية، مع دعم LTR داخل النصوص المستخرجة.
- حجم المصدر الأقصى 30 MiB للصور وملفات PDF، وملف واحد في كل عملية رفع ومعالجة.
- الصور والأشكال والشخصيات والحيوانات: 15 طبقة كحد أقصى.
- PDF لا يخضع لحد ثابت لعدد الطبقات، لكنه يخضع لحواجز أمان صريحة: 30 MiB
  للمصدر، و250 صفحة، و100,000 عنصر نصي مستخرج. تجاوز أي حاجز يفشل برمز
  واضح ولا يحذف طبقات بصمت.
- توافق Adobe النهائي بوابة Golden مستقلة داخل الإصدارات المستهدفة من
  Photoshop وAfter Effects؛ لا يُستبدل اختبار الملف البنيوي بهذه البوابة.

## 2. رحلة المستخدم المبسطة

1. يختار المستخدم «صورة» أو «PDF».
2. يرفع ملفًا واحدًا، وتظهر نسبة نقل البايتات الحقيقية مع الإلغاء وإعادة
   المحاولة.
3. ينشئ الخادم إصدار مصدر جديدًا داخل المشروع نفسه.
4. يعالج العامل الإصدار ويولّد `LayerDocument`.
5. تفتح مساحة العمل على المعاينة والطبقات الحقيقية فقط.
6. يصحح المستخدم مناطق محددة بالقلم، ويرتب ويسمي الطبقات.
7. تحفظ التعديلات تلقائيًا بمراجعة متفائلة تمنع الكتابة فوق نسخة أحدث.
8. تعرض بوابة التصدير الفحوص والتحذيرات والإعدادات قبل إنشاء الملف.
9. ينفذ عامل التصدير المهمة، ويمكن إلغاؤها أو استردادها بعد انقطاع العامل.

لا تعرض الواجهة تقدمًا أو جودة رقمية مصطنعة، ولا تستبدل الأصل برسم تجريبي
إذا فشلت المعاينة.

## 4. مساحة العمل

الترتيب المكتبي:

```text
┌──────── أدوات ضيقة ────────┬──────── معاينة مرنة ────────┬──── طبقات قابلة لتغيير العرض ────┐
│ أقلام مرتبطة بنوع المصدر  │ المصدر/الصفحة الفعلية      │ بحث، تحديد، رؤية، قفل، شفافية    │
│ اختصارات وحالة التوفر      │ Zoom وخلفية وشبكة وحدود     │ ترتيب، أسماء +، وثقة وتحذيرات    │
└────────────────────────────┴──────────────────────────────┴─────────────────────────────────────┘
```

- يوفر النظام مقياس مسافات أساسيًا `4/8/12/16px` للاستخدام التدريجي، لكن
  القيم الحالية ليست موحدة حرفيًا؛ تبقى قيم الكثافة الدقيقة، حدود البكسل
  الواحد، وأهداف اللمس استثناءات مقصودة حتى تمر كل هجرة عبر فحص بصري.
- الأعمدة الجانبية قابلة للطي، وعرض الطبقات محفوظ محليًا.
- في الهاتف تتحول الأدوات والطبقات والفحوص إلى لوحات سفلية واضحة.
- سجل الأدوات الحالي لا يملك حالة «مخطط لها»: كل أداة مسجلة تملك تنفيذًا
  حقيقيًا، وقد تظهر غير متاحة فقط عند غياب المصدر أو عند إغلاق قدرة تشغيلية
  مثل OCR الإقليمي أو Character Studio بواسطة بوابة إصدار موثقة.
- أسماء الطبقات تبدأ بعلامة `+` واحدة، وتمنع المحارف غير الصالحة لمسارات
  Adobe.

## 5. إصدارات المصدر والرفع

كل رفع ناجح ينشئ سجلًا مستقلًا في `source_versions`:

- `version_number` متزايد داخل المشروع.
- `sha256` ونوع المصدر والحجم والحالة محفوظة.
- المشروع يشير صراحة إلى `current_source_version_id`.
- استبدال المصدر لا ينشئ مشروعًا جديدًا ولا يمحو الإصدارات السابقة.
- سجل المشاريع يفتح أي إصدار جاهز بدقة.

المسار الفعلي:

1. `POST /v1/projects` للمشروع الجديد فقط؛ استبدال مصدر مشروع قائم يتجاوز
   هذه الخطوة ويحافظ على هوية المشروع
2. `POST /v1/uploads/intents` مع `projectId` داخل جسم الطلب
3. `PUT /v1/uploads/:uploadId/content`
4. `POST /v1/processing/jobs`
5. Poll على المهمة حتى `ready` أو `failed`

الخادم يتحقق من Magic Bytes والحجم، ولا يثق في الامتداد أو MIME القادم من
المتصفح. الإلغاء يغيّر جلسة الخادم، وليس واجهة العميل فقط.

الصيغ المقبولة:

- الصور: PNG, JPEG, WebP, AVIF, TIFF, BMP.
- الوثائق: PDF.

## 6. معالجة الصور

- الصور ذات Alpha تفصل المكونات المعتمة أولًا، ثم تلحق الحواف شبه الشفافة
  بأقرب مكون دون دمج جسمين بسبب جسر شفاف ضعيف.
- إعادة تركيب الطبقات تحفظ كل البكسلات المرئية.
- إذا زادت المكونات على 15 تحفظ أكبر 14 وتجمع البقية في
  `+تفاصيل_مجمعة` دون إسقاطها.
- الصورة المعتمة أو المتصلة تبدأ كطبقة Raster أصلية صادقة.

الأقلام الفعلية:

- **ملء/احتفظ:** يقوي المنطقة المحددة داخل الطبقة.
- **استبعاد:** يزيل المنطقة من الطبقة.
- **فصل:** ينشئ طبقة Raster مستقلة، ثم يملأ موضعها من البكسلات المحيطة في
  الخلفية المكررة.
- **ممحاة الإرشاد:** تحذف stroke قبل الإرسال.

الفصل والملء يخضعان لحد 15 طبقة. تحذير مراجعة الخلفية يظهر بعد الملء
التلقائي ولا يُستبدل بنسبة جودة ثابتة.

## 7. معالجة PDF

أنماط إعادة التحليل على إصدار المصدر نفسه:

- عناوين
- موضوعات
- جمل
- أسطر
- كلمات
- حروف

كل صفحة تملك طبقة `+page_NNN_background` بيضاء، ثابتة، ومقفلة. وحدات النص
تحفظ:

- النص الكامل.
- موضعه وأبعاده.
- الصفحة واتجاه الكتابة.
- ترتيب القراءة.
- اسم طبقة مشتق من المحتوى ويبدأ بـ`+`.

قلم PDF ينشئ مناطق `heading`, `line`, `topic`, `ignore`. تغيير نمط التقطيع
يعيد تحليل الإصدار نفسه بعد تأكيد المستخدم لأن المناطق والمراجعة الحالية
ستعاد تهيئتها.

النص المضمّن هو المسار الأول. الصفحات المصورة تستخدم OCR عربيًا محليًا،
ولا ترسل محتواها إلى خدمة شبكة. الفشل يعيد `OCR_FAILED` بدل إنشاء نتيجة
فارغة تبدو ناجحة.

## 8. عقود المهام والاسترداد

تستخدم مهام المعالجة والتصدير الحقول التالية:

- `attempt` و`maxAttempts`.
- `nextAttemptAt`.
- `leaseOwner` و`leaseExpiresAt`.
- `errorCode`.

العامل:

1. يطالب بالمهمة ذريًا باستخدام PostgreSQL و`SKIP LOCKED`.
2. يزيد رقم المحاولة ويجدد العقد أثناء العمل.
3. لا يحفظ الوثيقة أو الملف إذا فقد العقد.
4. يعيد المحاولة بتأخير تصاعدي حتى الحد الأقصى.
5. يسترد المهمة تلقائيًا إذا توقف عامل بعد انتهاء العقد.
6. يحولها إلى فشل نهائي واضح عند استنفاد المحاولات.

عاملا الصور وPDF يستخدمان مشغّلًا مشتركًا بدل نسختين مكررتين من منطق
المطالبة والاتصال والتسجيل. عامل التصدير مستقل لأن دورة الملف والإلغاء
والتحقق مختلفة.

## 9. المعاينة والحفظ

- الصورة تعرض أصول Raster المخزنة وبحدودها الفعلية.
- PDF يعيد بناء النص حسب مواضع الصفحة مع الخلفية البيضاء المستقلة.
- البحث والرؤية والقفل والشفافية و`zIndex` وترتيب القراءة تعديلات حقيقية.
- الحفظ يستخدم `baseRevision`; التعارض يعيد HTTP 409 ويوقف الحفظ، ثم يطلب
  تأكيد تحميل النسخة الأحدث. يستطيع المستخدم البقاء لنسخ التعديلات المحلية،
  لكن لا يستأنف الحفظ قبل تبني النسخة الأحدث.
- جودة المعاينة «سريعة/كاملة» لا تغير جودة الملف النهائي.
- لا توجد مقارنة «قبل/بعد» إلا عند توفر أصلين حقيقيين؛ الفرع الزائف محذوف.

## 10. التصدير

كل تصدير يمر عبر فحوص:

- الاسم يبدأ بـ`+` ولا يحتوي مسارًا أو محارف تحكم.
- حد 15 طبقة لمشاريع الصور.
- خلفيات PDF موجودة ومقفلة.
- أصول Raster موجودة وتطابق الحجم وSHA-256.
- الأبعاد آمنة للصيغة المختارة.

الصيغ الحالية وفق عقد `exportFormatsByProjectKind` المشترك بين API
والاختبارات:

<!-- export-capabilities:start -->
| معرّف الصيغة | الصور | PDF |
|---|---:|---:|
| `psd` | نعم | نعم، مجموعات دلالية ونص Raster |
| `png-layers-json` | نعم | نعم، المصدر والخلفيات والمواضع |
| `layered-tiff` | نعم، صفحة كاملة المساحة لكل طبقة Raster | — |
| `transparent-pngs` | نعم، حزمة PNG كاملة المساحة | — |
| `txt` | — | نعم |
| `csv` | — | نعم |
| `json` | — | نعم |
<!-- export-capabilities:end -->

يرفض الخادم `layered-tiff` و`transparent-pngs` لمشاريع PDF برمز
`EXPORT_FORMAT_UNSUPPORTED`؛ لا يعيد تسمية ملف مسطح ولا يستبدل الصيغة
المطلوبة بصمت.

مجموعات PSD في PDF تحمل أسماء الدلالة مثل العنوان والسطر والموضوع، وتظل
الخلفية طبقة مستقلة مقفلة. لا يُعاد تسمية ملف مسطح بامتداد PSD/TIFF.

## 12. الأمان والخصوصية

- جلسات HttpOnly/Secure، وMFA، واسترداد مشفر.
- RBAC في طبقة الخدمة، وتدقيق لأعمال الإدارة والفوترة.
- Zod عند الحدود، وSQL parameterized، وrate limit.
- CSP وHSTS وCORS مقيد بالأصل.
- S3 خاص مع `sse-s3` أو Bucket Default متحقق منه بعد الكتابة؛ وضع `none`
  محصور في التطوير. تدعم العمليات IAM/Workload Identity أو اعتمادًا مؤقتًا،
  وتتحقق من SHA-256 والحجم عند قراءة المصدر والمشتقات والتصدير. لا تسجل
  البايتات أو الأسرار أو النص الكامل للمستند.
- الدفع عبر صفحة مستضافة؛ التطبيق لا يستقبل أرقام البطاقات.
- `/internal/metrics` داخل شبكة التطبيق فقط، ولا يمر عبر Nginx العام.

## 13. القياس والتشغيل

المتوفر:

- صحة: `/v1/health/live` و`/v1/health/ready`.
- JSON logs باسم الخدمة والسياق ومعرف الطلب.
- Prometheus HTTP count/duration وprocess uptime على `/internal/metrics`.
- حالات المحاولة والعقد ورمز الفشل مرئية في API ولوحة الإدارة.

الأهداف الأولية:

- توافر 99.9%.
- p95 لطلبات API غير الثقيلة أقل من 300ms.
- تنبيه عند نمو انتظار الطابور، انتهاء العقود، أو ارتفاع الفشل النهائي.
- RPO لا يتجاوز 15 دقيقة وRTO لا يتجاوز 4 ساعات، بعد تأكيدهما تجاريًا.

## 14. بوابات الجودة

`npm run quality` ينفذ بالتتابع:

1. فحص حدود العمارة وملفات النشر.
2. ESLint.
3. Knip للكود والاعتماديات الميتة.
4. TypeScript strict.
5. الاختبارات مع بوابات تغطية لكل حزمة.
6. بناء كل التطبيقات والحزم.

التغطية الحالية مقيدة بحد أدنى لا يمكن أن يتراجع. منطق مساحة العمل يتجاوز
80%، ومعالجة الصور تتجاوز 90%. الحزم الأقل من 80% لها ratchet حالي ويجب
رفعها باختبارات حالات فعلية، لا بخفض نطاق القياس.

CI يبني صور Docker بعد نجاح الجودة ويفشل عند ثغرات production عالية.
كما يشغّل PostgreSQL 17 ونسخة MinIO مثبتة، يطبق migrations مرتين لإثبات
idempotency، ثم يختبر الاسترداد الذري للعقود ودورة كتابة/قراءة/حذف حقيقية.
