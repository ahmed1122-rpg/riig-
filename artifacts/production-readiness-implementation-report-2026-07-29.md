# تقرير تنفيذ واستكمال الجاهزية — MotionPrep

**تاريخ الإقفال المحلي:** 2026-07-30  
**القرار:** بوابات البنية الأساسية والكود والإعداد والبناء داخل حاوية Linux
والطوبولوجيا الإنتاجية المحلية مكتملة وناجحة، لكن **لم يُمنح اعتماد إنتاج
نهائي** لأن تمارين المزود والاستعادة والنشر الموقّع تحتاج بيئة خارجية، ولأن
بوابة دقة OCR على المسوح التاريخية الحقيقية لم تبلغ هدف الإصدار بعد.

## 2. الأعطال والنواقص التي أُغلقت

### أمان وإصدار

- فرض TLS في إعداد الإنتاج، ومنع إعدادات PostgreSQL/Redis/SMTP/S3 غير المشفرة.
- منع أي صورة إنتاج بلا `sha256` ثابت، والتحقق من تطابق صور الخدمات بين
  Compose المحلي وCI.
- نقل فحص صورة الويب إلى نفس Job البناء حتى لا يعتمد على صورة محلية مفقودة
  في Runner آخر.
- ترتيب التوقيع بعد نجاح فحص الصورتين والـsmoke، ثم التحقق من التوقيع بهوية
  المستودع والمرجع المحددين.
- تثبيت صور Node وNginx وPostgreSQL وRedis وMinIO وMailpit، وتثبيت جميع GitHub
  Actions إلى commit SHA كامل.

### البيانات والترحيلات

- إضافة checksum دائم للترحيلات وقفل PostgreSQL يمنع سباق مترحلَين.
- إصلاح تعارض أرقام الترحيلات.
- إضافة `019_upload_url_compatibility.sql` لإصلاح قواعد سبق أن طبقت إعادة تسمية
  مباشرة؛ يبقي `object_url` و`upload_url` متزامنين ويسمح بتعايش الإصدارين N
  وN+1 والتراجع إلى N.
- إضافة `020_worker_duration_metrics.sql` لعدادات ومجاميع وBuckets تراكمية
  صحيحة دلاليًا بدل histogram مبني على نافذة زمنية غير تراكمية.

### التشغيل والمراقبة

- heartbeats مستقلة لكل نوع عامل، مع سطر `worker_up=0` صريح عند غياب النوع
  بالكامل حتى لا تصبح تنبيهات Prometheus عمياء بسبب غياب السلسلة.
- فصل أحداث retry/lease الحديثة عن مقاييس المدة التراكمية.
- احتفاظ افتراضي لأحداث العمال 30 يومًا وتنظيف قابل للاختبار.
- منع فشل تسجيل حدث ثانوي من تحويل مهمة تصدير اكتملت بالفعل إلى فشل حلقة
  العامل.
- إضافة حدود الموارد، readiness للتبعيات، وتنبيهات توقف العامل/قدم الطابور/
  الفشل/فقد العقد/عدم الجاهزية.

### التخزين والتعافي

- إصلاح فحص التخزين ليمرر فعلًا `requireVersioning=true` إلى عميل S3؛ قبل
  الإصلاح كان المتغير موجودًا في Workflow من دون تفعيل استدعاء
  `GetBucketVersioning`.
- تفعيل Versioning في MinIO المحلي والتكاملي وجعله مطلوبًا في بيئة المثال.
- إضافة manifest استعادة منسق يربط نسخة PostgreSQL ونسخة التخزين وdigests
  الإصدار ونتائج الرحلة المستعادة ويقيس RPO/RTO.

### الواجهة والكفاءة

- كشف اختبار المتصفح عطلًا عالي الخطورة: زر قائمة الهاتف موجود في DOM لكنه
  مخفي بسبب انعكاس أولوية `!important` بين CSS layers، ما كان يمنع الضيف من
  الوصول إلى التسجيل. أزيل التعارض وأضيف عقد breakpoint نهائي للهاتف وسطح
  المكتب.
- النتيجة المقاسة: لا أزرار مرئية أصغر من 44×44px، ولا نص تطبيقي مرئي أصغر
  من 12px، والنص العادي لا يقل عن 14px.
- إضافة ميزانية bundle مضغوطة وفحص تلقائي للأصول البصرية.
- توحيد Node على `>=22.12.0`، وتحميل البيئة تلقائيًا، وجعل أمر التنظيف يرفض
  المسارات المتتبعة أو الواسعة.

## 4. الأدوات والوظائف غير المكتملة

لا توجد أداة معروضة كجاهزة للمستخدم ثم تُخفي فشلًا صامتًا. الأدوات التالية
مصنفة صراحةً `planned` وتُحجب من سطح الإنتاج:

| الأداة | ما يلزم قبل نقلها إلى `ready` |
|---|---|
| تحسين حواف الصورة | عامل يولد Raster مشتقًا، عقد حفظ/مراجعة، قياسات جودة واختبارات |
| دمج طبقات الصورة | دمج غير هدّام مع مراجعة قابلة للاستعادة وrollback |
| إعادة OCR لمنطقة | تمرير قصاصة من الصفحة الأصلية إلى العامل وعقد OCR إقليمي |
| فصل وحدة نصية PDF | تحرير geometry والعلاقات وترتيب القراءة على الخادم |
| دمج وحدات PDF | دمج المحتوى والهندسة وإعادة فهرسة ترتيب القراءة |
| استعادة إصدار مصدر | تبديل آمن للإصدار الحالي مع تدقيق وتوافق التصدير |

أعمال منتج/تشغيل إضافية موصى بها بعد إثبات الإطلاق الأول:

1. حذف/استعادة المشروع بسياسة retention وسجل إداري.
2. OpenAPI مولد ومتحقق منه في CI.
3. اختبار حمل وذاكرة بمزيج PNG/PDF حتى 30 MiB وقياس p95 وRSS.
4. تدريب/اعتماد نموذج عربي محلي مخصص للمسوح التاريخية على development فقط،
   والاختيار على validation ثم فتح holdout v3 جديد مرة واحدة. corpus الحالي
   توسع إلى 51 صفحة، ودُمج منتقي حتمي يعتمد على خصائص الصفحة فقط وينفذ
   استدراكًا واحدًا كحد أقصى. قِيس كذلك `ara+eng` وPaddleOCR وCLAHE ورفع
   الدقة وحذف الكلمات منخفضة الثقة، ورُفضت البدائل الأعلى كلفة أو التي تغيّر
   اكتمال النص. فتح holdout v2 بعد تجميد التنفيذ ونجح عند 10.43%؛ لا تُستخدم
   مراجعه في المواءمة ويلزم جيل v3 من مصادر جديدة للدورة التالية. التفاصيل في
   `artifacts/benchmarks/ocr-arabic-corpus/report.md`.

## 5. البوابات المتبقية قبل اعتماد الإنتاج

1. **إنشاء Git baseline ودفعه.** جميع ملفات مساحة العمل حاليًا `untracked`،
   لذلك لا يوجد commit ثابت يمكن ربط CI أو التوقيع به.
2. **تشغيل `provider-readiness`** بهوية workload وحاوية المزود الفعلية.
3. **تمرين استعادة معزول وموقّع** يثبت RPO ≤ 15 دقيقة وRTO ≤ 4 ساعات.
4. **نشر وتراجع clean-runner بالـdigest الموقّع** دون إعادة بناء.
5. **فتح Golden في Photoshop وAfter Effects المرخصين.**
6. **رفع OCR الحقيقي إلى حد القبول لكل صفحة.** corpus الحقوقي والقياس
   وموانع الانحراف موجودة الآن. نجح CER الرسمي عند 19.00% وholdout v2
   المستقل عند 10.43%، لكن `npm run benchmark:ocr:corpus` يفشل عمدًا لأن
   صفحة جدول development واحدة عند 69.02% تتجاوز حد 50%. خفّض المنتقي
   الحتمي وقص الهامش والمرور الإنجليزي المحلي العدد من ست صفحات إلى واحدة.
   تجارب فصل/تدوير الجدول وإسقاط الخطوط وصلت فقط إلى 68.92% و67.71% و66.30%
   فلم تُدمج. يجب تثبيت holdout v3 من كتب أخرى قبل أي تعديل جديد للتنفيذ.

أثبت تدقيق 2026-07-30 أن البيئة الحالية لا تحتوي متغيرات اعتماد مزود التخزين،
وأن Git بلا `HEAD` أو remote أو هوية مؤلف. كما أثبت الفحص أن Photoshop
27.8.0.13 يقف عند شاشة بدء فترة تجريبية/شراء، وأن After Effects 26.3 لا
ينشئ نافذة ويبقى غير عامل. لم تبدأ فترة تجريبية ولم تُؤتمت مصادقة أو عملية
شراء. لا يجوز اختلاق هذه المدخلات أو اعتبارها ناجحة ضمن دليل محلي.

## 6. ترتيب الإقفال المقترح

1. مراجعة ملفات baseline ثم commit/push وتلقي CI أخضر.
2. تنفيذ بوابة التخزين الفعلية.
3. نشر staging بالـdigests الموقعة وإجراء rollback.
4. تنفيذ تمرين الاستعادة وتوقيع manifest.
5. إقفال Adobe، وتحسين OCR حتى تمر بوابته دون إضعاف الحدود، ثم قرار
   Go/No-Go موثق.

لا يُستخدم تعبير «جاهز للإنتاج» قبل نجاح البنود 1–4 على الأقل. أما البنود
الخاصة بأدوات المنتج المخططة، فيمكن جدولتها بعد الإطلاق ولا تعطل المسار
الأساسي الحالي ما دامت مخفية بوضوح.
