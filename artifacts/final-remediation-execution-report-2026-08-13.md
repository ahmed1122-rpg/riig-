# تقرير التنفيذ والإغلاق المحلي — 2026-08-13

## الملخص التنفيذي

اكتملت محليًا مراحل الإصلاح المتتابعة لمرشح الإصدار `0.1.8`، بما يشمل سلامة البيانات،
أمن الحسابات، معالجة PDF، بنية الطبقات، المزامنة، حالات الواجهة الصامتة، القياس،
التغليف، واختبارات مسار الإنتاج المحلي.

النتيجة الحالية:

- **الشفرة جاهزة محليًا لتكوين مرشح إصدار.**
- **النشر العام ما زال NO-GO تشغيليًا** إلى أن تُثبَّت الشفرة في commit/tag نظيف،
  وتُبنى الصور وتُوقع، وتنجح بيئة managed staging والاستعادة والـcanary لنفس SHA/digests.
- لم يُنفذ `git add` أو commit أو tag أو push أو نشر خارجي.

## نطاق المراجعة والتنفيذ

شمل العمل تطبيقات الويب والـAPI وعمال المعالجة والتصدير والشخصيات، حزم معالجة
المستندات والوسائط والطبقات، PostgreSQL وRedis وS3/MinIO والبريد، Docker وNginx،
Workflows، Prometheus، العقود والهجرات، اختبارات الوحدة والتكامل والمتصفح، وأدوات
الصيانة والأمن والنشر.

## ما أُنجز

### 1. سلامة البيانات والعمليات المتزامنة

- أصبحت عمليات enqueue مع project fence ذرية، وأصبحت claim/settlement محكومة بـCAS.
- مُنعت استعادة أو حفظ مصدر قديم أثناء رفع أو job نشط، وأضيف flush قبل تغيير المصدر.
- أُغلقت سباقات retry والتصادمات، ومنع تحويل job قديم عند اصطدام المعرّفات.
- أضيف منسق موحد لأوامر الوثيقة مع stale-result guard وundo/redo متسق.
- أضيفت حواجز حذف الحساب: tombstone، drain، final inventory، object-write leases،
  permanent version purge، وترتيب أقفال ثابت لتجنب deadlock.
- أضيفت حواجز قاعدة بيانات تمنع إنشاء مشاريع أو أعمال أو اشتراكات أو نشر أصول بعد
  بدء حذف الحساب.

### 2. PDF والطبقات والمعاينة

- كل صفحة PDF لها مجلد بنيوي باسم `+page_NNN`، والخلفية والنصوص والمجموعات الدلالية
  أبناء له؛ التخزين والتصدير يحافظان على الشجرة.
- أصبحت عدادات الصفحة والإجمالي منفصلة وصادقة، والبحث عابرًا للصفحات دون فتحها كلها.
- أضيفت شجرة طبقات مشتركة لسطح المكتب والهاتف مع disclosure، حالة الصفحة الحالية،
  RTL، اقتطاع الأسماء، وحماية التنقل من فقد التعديلات.
- أضيفت رؤوس مجلدات صفحات ثابتة أثناء التمرير، ومسار هرمي للطبقة النشطة، وسجل موحد
  لفروق عمليات الوثيقة يوضح عدد وأسماء الطبقات المضافة والمحذوفة والمعدلة والمراجعة الناتجة.
- المجموعات البنيوية لا تُعامل كطبقات محتوى قابلة للتحرير أو الرسم في معاينة التصدير.
- أضيف تحقق domain موحد لاكتشاف duplicate IDs/names، orphan parent، cycles،
  cross-page parent، parent غير مجموعة، والمجموعات الفارغة.
- أضيفت أوامر حقيقية للتسمية، الترتيب، عكس ترتيب القراءة، الإظهار/الإخفاء، القفل/الفتح،
  النقل، الدمج والفصل، مع حد آمن للعمليات الجماعية ومعاينة diff قبل الأوامر الواسعة.
- أضيف محرر خصائص للطبقة: bounds والاتجاه والمحاذاة والخط والحجم والشفافية والرؤية والقفل،
  مع اختيار الطبقة من المعاينة وتوحيد z-order/reading order/solo.
- أصبحت المحاذاة المنطقية `start/center/end/justify` محفوظة من الواجهة عبر autosave وAPI،
  وتظهر في معاينة PDF وتنتقل إلى JSON/CSV وPSD؛ ويُرفض دمج نصوص مختلفة المحاذاة مبكرًا.
- زر «ملاءمة» في معاينة التصدير يحسب التكبير من أبعاد الحاوية والمعاينة الفعلية، ويعيد
  القياس عند تغير المساحة ما دام وضع الملاءمة نشطًا، بدل قيمة ثابتة مضللة.
- رُفعت قابلية التعامل إلى fixture يحوي 100,000 طبقة عبر فهرسة O(n)، نافذة DOM
  محدودة؛ تبدأ الصفحة المفتوحة بـ80 صفًا ثم تحمل 160 صفًا في الدفعة، مع بحث مؤجل،
  مرشحات، تحميل تدريجي، وسجل أوامر.

### 3. سلوك الواجهة والمزامنة والكاش

- وُحد polling للمشاريع والتصديرات والنشاط وCharacter Studio ومسار المشروع في hook
  مشترك يدعم إلغاء الطلب، إزالة التكرار، منع الطلبات المتوازية، visibility/online،
  exponential backoff مع jitter، واحترام `Retry-After`.
- أُصلحت الحالات الصامتة في Billing وProjects وExports وMFA؛ أصبح loading/error/empty/
  expired ظاهرًا ولا يُعرض اشتراك افتراضي مزيف عند فشل الخادم.
- أُزيلت حراسة `beforeunload` المكررة وأصبح لها مالك واحد مرتبط بحالة التعديلات الفعلية.
- وُحد تنزيل الملفات عبر helper واحد يزيل عنصر الرابط ويلغي Object URL حتى عند الفشل.
- بقي حد رفع PDF عند **30 MiB**؛ القراءة محدودة والتزامن FIFO قابل للضبط، والحجم الفعلي
  فوق الحد يُرفض بـ413 دون الاعتماد على `Content-Length` وحده.

### 4. الأمن والخصوصية

- أضيف email verification أحادي الاستخدام، resend غير كاشف، وadmin bootstrap أحادي المرة.
- أضيف MFA keyring قابل للتدوير، سباقات atomic لـTOTP/recovery، وترقية progressive إلى
  `scrypt$v2` بعد دخول ناجح فقط.
- فُصلت هويات وأسرار migration/API/maintenance/workers، ومستخدمو DB وصلاحيات S3.
- أضيف log redaction وCSP report-only endpoint منقح ومحدود، وفحوص أمن وترخيص.
- `npm audit --audit-level=high` لا يسجل أي ثغرة معروفة.

### 5. الأداء والقياس

- أضيف client telemetry محدود ومُنقح لأخطاء React/runtime وunhandled rejection وLCP،
  مع منع cookies والحقول غير المحدودة وتقليل التكرار.
- أضيفت مقاييس Prometheus وتنبيهات LCP وأخطاء العميل وغياب الـAPI/metrics وحالة العمال.
- أضيف drain تشغيلي واضح وdeadline صلب لعامل التصدير مع إعادة تدوير العملية عند التعليق.
- تُستخرج خرائط المصدر من المجلد العام إلى حفظ خاص بعد البناء.
- يتحقق bundle budget من manifest الحقيقي، طلبات البداية، hero، الخطوط الحاجبة،
  إجمالي JS/CSS، وحجم كل chunk.

### 6. البناء والنشر

- ثُبتت Workflows على action SHAs وتتحقق أداة النشر من YAML graph الفعلي لا من تعليقات النص.
- عُزلت منافذ E2E، وأصبح اختبار topology يخصص منافذ loopback شاغرة تلقائيًا مع رفض التكرار.
- صورة runtime تتحقق من كل الحزم الانتقالية، وworker health مرتبط بالـinstance والنوع وrelease SHA.
- أضيف `/readyz` منفصل عن liveness، وفحوص fault recovery وload وrelease evidence.

## أخطاء خفية كُشفت أثناء الإغلاق

- اختبار coverage لعامل التصدير لم يكن يمر بمسار انتهاء المهلة؛ أضيفت حالة تثبت التسجيل
  وإعادة التدوير بدل خفض السياسة.
- verifier الحزمة كان يستخدم `violations` قبل تعريفها؛ صُحح وأضيفت عقود manifest أدق.
- فحص Workflow أمكن نظريًا خداعه بتعليق نصي؛ حُول إلى تحليل YAML واختبار يمنع ذلك.
- منفذ PostgreSQL الافتراضي كان مشغولًا بstack آخر؛ بدل حذفه أصبحت المنافذ تُحجز آليًا.
- اختيار أول عنصر بعد تحميل PDF كان يختار page group بنيويًا؛ أصبح يختار أول طبقة محتوى.
- ExportReview كان يسمح بتعديل group ثابت ويرسم اسمه داخل المعاينة؛ أصبح content-only.
- التنزيلات و`beforeunload` وpolling كانت موزعة في نسخ متقاربة؛ وُحدت بعقود مشتركة.
- كشف QA الحي 6 مخالفات وصول مؤكدة في شجرة PDF ومعالم الصفحة وزر حالة المصدر الفارغ؛
  أُصلحت دلالات الصفوف والمجموعات، أزيل `main` المتداخل، أضيف `h1`، وسُمّي زر التفاصيل.

## ما لم يُثبت بعد

- الاختبار المحلي لا يثبت TLS/IAM/PITR/SMTP أو سياسات S3 لدى مزود الإنتاج.
- لا توجد بعد صور `0.1.8` موقعة ومرتبطة بالـSHA الحالي.
- لا يوجد clean commit أو tag `v0.1.8` أو hosted CI لهذا التغيير الكبير.
- لم تُنفذ managed-staging restore/load/rollback/canary على الـdigests النهائية.
- اختبار 20×29.961MiB المحلي نجح، لكنه لا يحل محل حمل managed staging المربوط بـSHA وdigests موقعة.
- regional OCR وCharacter Studio وlive billing تحتاج أدلة مزود مستقلة قبل تفعيلها.

## خطة الإطلاق النهائية

1. **مراجعة التغيير وتثبيته:** مراجعة diff الكبير، تقسيمه إلى commits مفهومة أو commit
   مرشح واحد وفق سياسة الفريق، ثم إعادة quality من checkout نظيف.
2. **مرشح الإصدار:** إنشاء tag `v0.1.8` بإذن المالك وتشغيل hosted CI على SHA المطابق.
3. **سلسلة التوريد:** بناء الصورتين، فحصهما، توقيعهما بـCosign، وتسجيل digests وSBOM.
4. **Managed staging:** نشر نفس digests والتحقق من PostgreSQL/Redis/SMTP/S3/TLS/IAM
   والهجرات والحسابات ذات أقل صلاحية.
5. **الاستعادة والأداء:** restore drill موقّع يثبت `RPO ≤ 15m` و`RTO ≤ 4h`، ثم حمل PDF
   ممثل حتى 30 MiB ومراقبة queue age/error rate/RSS/LCP.
6. **الـcanary والرجوع:** canary محدود على نفس SHA/digests، اختبار rollback، ثم توسيع
   تدريجي مع بوابة إيقاف واضحة.
7. **تفعيل الميزات الحساسة:** إبقاء OCR الإقليمي وCharacter Studio والفوترة الحية خلف
   feature flags إلى أن تنجح أدلتها المنفصلة.
