## 3. ما كان خاطئًا وما تم إصلاحه

### 3.1 الكود القديم والميت

- حُذف ملف العينات القديم `sampleAssets.ts` الذي خالف عقد `LayerDocument` وكسر الأنواع والبناء.
- حُذفت سكربتات `rebuild-web.mjs` و`serve-web.mjs` غير الموصولة، بما فيها مسار خادم ثابت غير مناسب للاعتماد الإنتاجي.
- حُذف نظام Toast غير المستخدم بدل إبقائه كواجهة ميتة أو إصلاح استيراد شكلي فقط.
- استخرجت مساعدة اختصارات مساحة العمل إلى `useWorkspaceShortcutHelp` بدل إبقاء المنطق داخل المكوّن الكبير.
- النتيجة الحالية: `knip` يمر من دون ملفات أو exports أو dependencies غير مستخدمة.

### 3.2 الملفات الضخمة والتداخل المعماري

تم تفكيك الملفات التي كانت تجمع مسؤوليات متعددة إلى وحدات متماسكة:

- المعالجة: coordinators وjob claim/executor وعمليات طبقات الصورة وPDF وحالة الطبقة.
- التصدير: قارئ الأصول وباني artifact مستقلان عن خدمة orchestration.
- العقود: فصل core/layer/workflow contracts.
- معالجة PDF: فصل المصدر والتخطيط وOCR والمناطق والأخطاء.
- الواجهة: فصل Workspace إلى layout وdialogs وcommands وoperations وnavigation guard وproject lifecycle وtool controller وsource restoration.
- مراجعة التصدير: فصل الرأس والمعاينات وحالة الحوار.
- الفوترة: فصل حوار checkout عن البوابة الرئيسية.

التحقق الحالي: **295 ملف إنتاجي، صفر ملفات كبيرة grandfathered، وصفر كتل نسخ دقيقة**. لا توجد دورة imports أو خرق مثبت لحدود الوحدات.

### 3.3 انحراف سلوك وضع الضيف

كان النص التسويقي يوحي بإمكانية تجربة الرفع كضيف، بينما أول تفاعل فعلي يحتاج جلسة. أصبح العقد واضحًا ومتسقًا:

- الضيف يستكشف الاستوديو والمساحة.
- اختيار الملف والرفع والحفظ والتصدير تتطلب تسجيل الدخول.
- الضغط على اختيار الملف يفتح المصادقة قبل تنشيط file picker.
- بقي فحص المصادقة داخل hook الرفع كدفاع إضافي ضد الاستدعاء المباشر.

هذا يغلق انحرافًا بين الوعد النصي والسلوك الفعلي، وليس مجرد تغيير صياغة.

### 3.4 تشوهات مساحة المشروع

تم إصلاح الأسباب البنيوية لا الأعراض فقط:

- نقل الإرشاد خارج طبقة تغطي أصل العمل.
- تطبيق container queries على شريط المعاينة والإرشاد.
- منع القص والتمرير الأفقي غير المقصود.
- نقل الأدوات الثانوية إلى قائمة إجراءات للطبقة مع أهداف لمس لا تقل عن 44×44px.
- إبقاء إجراء حفظ القناع كاملًا داخل viewport وفوق dock الهاتف.
- توحيد ارتفاع الشريط العلوي عبر `--topbar-height` بدل قيم متعارضة.
- فتح قوائم آخر صفوف الطبقات لأعلى حتى لا تُقص عند الحافة.

القياس المثبت على الهاتف 390×844: زر الحفظ بين `y=710..754`، والـdock يبدأ عند `y=760`. وعلى سطح المكتب: عرض وتمرير عمود المعاينة والإرشاد متساويان، من دون overflow مخفي.

### 3.5 لوحة المشروع والقوائم

- أعيد الشريط السفلي للهاتف إلى `position: fixed` داخل viewport بدل ظهوره في نهاية الصفحة.
- نُقلت ملكية هندسة الشريط إلى `app-shell-responsive.css` وحُذفت التعريفات السلوكية المتعارضة من ملفات workspace وprimitives.
- وُحّد عقد القوائم المتنقلة عبر `useModalDrawer`: عزل الخلفية بـ`inert`، `aria-modal`، حصر التركيز، إغلاق Escape، واستعادة التركيز إلى زر الفتح.
- أصبحت قائمة الإدارة على الهاتف حوارًا فعليًا وليست aside مرئيًا فقط.
- صُممت صفوف مستخدمي الإدارة كبطاقات تعريفية مقروءة، مع بريد كامل وحالات حساب عربية ونص 14px.
- استُثمر الفراغ الكبير في لوحة الإدارة بإضافة ملخص خط الإنتاج وأحدث النشاط من بيانات الخادم المتاحة.

### 3.6 مراجعة التصدير

كان زر إنشاء ملف التصدير جزءًا من الجسم الطويل للحوار، ما يجعله يختفي أسفل قائمة الطبقات على الهاتف. نُقل إلى footer مستقل وثابت داخل شبكة الحوار، بينما يتمرر الجسم وحده.

القياس على 390×844: الجسم قابل للتمرير (`723/2058`)، والـfooter بين `y=779..844`، وزر التصدير بين `y=790..834`.

### 3.7 CSS والمسارات المرئية

- حُدد مالك صريح لسلوك shell والتنقل المتنقل.
- أزيل تكرار سلوك `.mobile-bottom-nav` من طبقات لا تملكه.
- بقيت طبقة accessibility للتعديلات المرتبطة بالوصول فقط، لا لإعادة تعريف التموضع.
- نجح Stylelint وعقد طبقات CSS واختبارات geometry الموسعة.

لا يوجد حاليًا دليل على رابط route مكسور أو import مفقود ضمن المسارات التي يبنيها التطبيق وتغطيها الرحلات الآلية.

### P0 — خدمات الإنتاج المُدارة غير مثبتة

بوابات الإعداد ترفض plaintext وmutable image tags، لكن لم يُثبت الاتصال الفعلي في staging مع PostgreSQL TLS/PITR، Redis TLS/auth، S3 خاص ومشفر، SMTP، load balancer وTLS.

الإصلاح: smoke test ضد providers الحقيقيين، ثم rollback/restore drill موثق.

### P1 — تغطية الويب منخفضة

التغطية الحالية تجتاز الحد لكنها لا تكفي كهدف نهائي لواجهة تحرير كثيفة الحالات. أضعف المناطق: `App.tsx`، `Workspace` orchestration، Dashboard/Settings/Help، وبعض dialogs وAPI clients.

الإصلاح: لا ترفع النسبة عشوائيًا؛ أضف اختبارات لسلوكيات الفشل، الاستعادة، race conditions، autosave، navigation guard، admin filters، وتصدير متعدد الحالات. الهدف المرحلي المقترح: Web statements 40% وfunctions 30%، ثم 55%/45%.

### P1 — مسارات تشغيل API منخفضة التغطية

## 7. خطة الإغلاق بالتتابع

### المرحلة A — تثبيت مرشح الإصدار — مكتملة

1. إنشاء فرع `codex/release-hardening-2026-08-03`.
2. مراجعة مدخلات الحالة الـ90، وإضافة ملفات المصدر والتوثيق المقصودة فقط، مع استبعاد أي artifact محلي أو fixture مؤقت.
3. commit ذري واحد أو سلسلة commits مرتبة لا تترك البناء مكسورًا بين مراحلها.
4. تشغيل `npm run quality` و`npm run test:e2e` من checkout نظيف.
5. إنشاء evidence bundle يحمل SHA الكامل وdigests غير قابلة للتغيير.

**معيار القبول:** `git status --short` فارغ، والجودة وE2E خضراوان على SHA نفسه.

### المرحلة B — staging إنتاجي الشكل

1. تفعيل الخدمات المُدارة مع TLS والهوية الأقل صلاحية.
2. تشغيل migrations، readiness لكل dependency، وsmoke كامل للرفع/المعالجة/الحفظ/التصدير.
3. إثبات private object storage، encryption، versioning، lifecycle وsigned URLs.
4. إثبات SMTP/outbox/retry/reconciliation.

**معيار القبول:** لا readiness أخضر عند فقد dependency حرجة، ولا secret أو mutable image reference داخل الحزمة.

### المرحلة C — الاستعادة والفشل — مكتملة محليًا، ومتبقي staging مستضاف

1. rollback إلى الإصدار السابق مع migrations additive.
2. restore PostgreSQL + object storage إلى نقطة منسقة.
3. fault injection: worker loss، Redis delay، S3 failure، API restart، retry storm.
4. إثبات RPO/RTO الفعليين لا النظريين.

**معيار القبول:** كل job حساس replay-safe وidempotent، ولا حالة معلقة بلا reconciliation.

### المرحلة D — الأداء والمراقبة

1. sustained load لمسارات الصور وPDF والتصدير.
2. ضبط concurrency والموارد من القياسات.
3. لوحات وتنبيهات: p95/p99، queue age/depth، worker RSS/CPU، lease loss، failed jobs، storage/SMTP/auth failures.
4. تسجيل commit SHA وimage digest في logs والـmetrics.

### المرحلة E — رفع جودة الاختبارات

1. زيادة تغطية سلوك الويب وruntime API حسب المخاطر.
2. snapshots هندسية للحالات الممتلئة والفارغة والأخطاء.
3. إبقاء عتبات maintainability وbundle ratchets مانعة للرجوع.
4. إعادة فتح OCR فقط بعد holdout مختوم حديث.

## 8. قرار النشر

- **مرشح الكود `e7119472…` صالح للدمج بعد نجاح CI البعيد.**
