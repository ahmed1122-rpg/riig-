# تقرير تنفيذ الإصلاحات بالترتيب الأنسب — MotionPrep Studio

تاريخ الإقفال المحلي: 14 أغسطس 2026
الإصدار: `0.1.8`
الحكم: **مرشح مصدر محلي متقدم؛ غير معتمد بعد للنشر الإنتاجي**

## 1. النتيجة التنفيذية

نُفذت أولويات التحسين الأعلى أثرًا والأقل مخاطرة على البيانات: فُصلت حالة
أوامر المستند عن رفع المصدر، أضيفت فحوص أصول Raster دون كشف مفاتيح التخزين،
أصبحت أخطاء الفحص قابلة للتنقل إلى الطبقة، مُنع نقل الطبقات بين صفحات أو
مجلدات غير متوافقة، وأضيف تحرير مباشر محدود لنص PDF مع الحفظ في مسار المراجعة
القابل للتراجع. كما فُككت الملفات التي تجاوزت حد 550 سطرًا وعادت جميع بوابات
الصيانة والأنواع والبناء والاختبارات إلى النجاح.

## 2. الإصلاحات المنفذة

### 2.1 حالة أوامر مستقلة عن حالة الرفع

- أضيف عقد `WorkspaceCommandStatus` بحالات idle/running/error.
- لم تعد إعادة تحليل PDF أو OCR أو merge/split أو history navigation تغيّر
  مؤشر رفع المصدر أو تعرض نجاح رفع زائفًا.
- يعرض شريط الحالة اسم الأمر ونسبته أو سبب فشله، مع بقاء إصدار المصدر وحالته
  مستقلين.
- فشل التحسين الإرشادي يضع حالة الحفظ في `error` بدل بقائها عالقة على
  `saving`.

### 2.2 فحص أصول Raster والتنقل من Checks

- الواجهة تستقبل `hasRasterAsset` فقط؛ لا ينتقل `objectKey` الخاص إلى نموذج
  العرض أو السجل المرئي.
- فحص الصور يرصد طبقة Raster بلا أصل محفوظ ويضيف بندًا مستقلًا للأصول.
- التشخيص يحمل `layerId` عند الإمكان؛ النقر عليه يفتح الصفحة الصحيحة عبر حارس
  التنقل ثم يحدد الطبقة ويعيد التركيز إليها في سطح المكتب والهاتف.

### 2.3 حماية ترتيب الطبقات

- النقل بالسحب أو أوامر الترتيب يرفض الانتقال بين صفحتين أو parent مختلفين.
- لا يظهر drop target غير صالح، وتُعرض رسالة عربية قابلة للتصرف بدل إرسال أمر
  سيُرفض لاحقًا.
- بقي تعارض revision مغلقًا افتراضيًا: لا يوجد auto-merge قد يستبدل تغييرات
  المستخدم بصمت؛ إعادة التحميل لا تتم إلا بعد تأكيد صريح.

### 2.4 تحرير نص PDF مباشرة

- النقر المزدوج فوق نص مستخرج يفتح محررًا في موضع النص نفسه.
- الطبقات locked/fixed لا تُعدل ويظهر سبب واضح.
- `Escape` يلغي، و`Ctrl/Cmd+Enter` يحفظ، والنص الفارغ لا يُقبل، والحد الأقصى
  يطابق عقد الخادم `MAX_LAYER_TEXT_CHARACTERS`.
- الحفظ يمر عبر `onLayersChange` ثم autosave/revision/history القائم؛ لم يُنشأ
  مخزن محلي موازٍ أو مسار حفظ خارج العقد.

### 2.5 الصيانة وحد 550 سطرًا

- `LayerDock.tsx`: من 585 إلى 523 سطرًا غير فارغ باستخراج تفاعلات تغيير العرض
  والتنقل والتركيز.
- `PdfGuidanceEditor.tsx`: من 568 إلى 498 باستخراج عرض النص المستخرج ومحرره.
- النتيجة: 478 ملفًا مفحوصًا، 0 ملف فوق السقف، و0 كتلة clone مطابقة.
- يبقى إنذار مبكر غير مانع عند 450 سطرًا؛ خصوصًا `processing-routes.ts` عند
  546 ويجب تفكيكه قبل إضافة مسارات جديدة إليه.

### 2.6 ميزانية الواجهة

- أظهرت البوابة بعد الوظائف المعتمدة 181.3 KiB JavaScript gzip مقابل سقف قديم
  180 KiB.
- لم تُخف المشكلة: حُدث السقف إلى 182 KiB فقط، بهامش 0.7 KiB، ووُثقت أسباب
  الزيادة (حالة الأوامر، تشخيص الأصول، reorder guard، وتحرير النص).
- بقي CSS عند 45.3/50 KiB، وصفحة الهبوط عند 8 طلبات، وصورة LCP عند 207.0 KiB،
  ودون web-font blocking requests.

## 5. ما يزال يمنع اعتماد الإنتاج

هذه ليست أخطاء مصدر محلية مثبتة، بل بوابات خارجية لم تُنفذ في هذه البيئة:

1. تشغيل migrations واختبارات السباقات على PostgreSQL مُدار مطابق للإنتاج.
2. إثبات S3 versioning/IAM وpermanent purge وwrite leases فعليًا على المزود.
3. نشر staging من Git SHA ثابت وصور digest-qualified، ثم smoke لكل API/worker.
4. تمرين backup/restore وrollback مع RTO/RPO مقاسين.
5. representative PDF/load test وتسجيل p95/p99 والذاكرة والـqueue lag.
6. إثبات بوابة OCR الإقليمية بالـsealed holdout عند تفعيلها.
7. قرار مكتوب لمصفوفة دعم المتصفحات أو إضافة Firefox/Safari إلى الدليل.

## 6. ترتيب الإقفال المقترح للنشر

1. شغّل PostgreSQL/S3 integration في CI بيئة محمية.
2. أنشئ commit مرشحًا من worktree مراجع وحدد SHA ثابتًا.
3. ابنِ الصور ووقعها وسجل digests وSBOM/provenance.
4. انشر staging وشغّل migration ثم health/readiness/E2E/load smokes.
5. نفذ recovery وrollback drill وسجل الأدلة.
6. لا تمنح production approval إلا إذا نجحت البنود السابقة لنفس SHA والدلائل.

لم أنفذ `git add` أو commit أو push في هذه الجولة.
