# المراجعة الشاملة وخطة استكمال MotionPrep Studio

**التاريخ:** 2026-08-12
**الفرع المفحوص:** `codex/sequenced-remediation`
**الإصدار:** `0.1.7`
**القرار الحالي:** **غير جاهز للدمج أو الإنتاج** حتى إغلاق بوابات P0 ثم تنفيذ بوابات البيئة الخارجية.

## 1. نطاق المراجعة وافتراضاتها

- راجعت فهرس مساحة العمل (1,166 ملفًا وقت القياس، منها 432 TypeScript و76 TSX و91 سكربت MJS) و12 مساحة npm: API وWeb وأربعة عمال وست حزم مشتركة.
- فُحص التغيير الحالي كاملًا: 24 ملفًا، `+682/-85`. هذه تغييرات موجودة مسبقًا في مساحة العمل ولم تُعدّلها هذه المراجعة.
- شغلت بوابات الأنواع والبناء والاختبارات والتغطية وE2E والعقود والمعمارية والأمن والحزم والأصول والاسترداد والتنبيهات، ثم نفذت اختبار استخدام حقيقي على سطح المكتب والهاتف.
- الافتراض التشغيلي: المطلوب تقرير وخطة فقط، لا تنفيذ إصلاحات المصدر في هذه الجولة. الحالة الإنتاجية لا تُستنتج من نجاح محلي؛ يلزم دليل مستضاف مرتبط بنفس SHA والصور غير القابلة للتغيير.

## 2. الخلاصة التنفيذية

البنية الأساسية قوية ومناسبة: modular monolith مع عمال منفصلين، PostgreSQL/Redis/S3 للإنتاج، عقود واضحة، 41 migration و75 عملية API، تحقق معماري ونشر واسترداد وتنبيهات جيد. لا توجد ثغرات npm معروفة، ولا ملفات ميتة مؤكدة، ولا اختبارات متروكة بـ`skip/todo/only`.

لكن المرشح الحالي تراجع عن خط أساس الجودة في ثلاث نقاط تمنع الدمج، ويحتوي عيبين عاليي الخطورة في مسودة PDF والإحداثيات، وثلاث مشكلات مؤكدة في الطبقات والإتاحة والأداء. أدوات Character وOCR الموضعي والفوترة الحية ليست «محذوفة» أو stubs؛ هي وظائف مكتملة جزئيًا ومقيدة ببوابات إصدار خارجية، ويجب أن تبقى معطلة افتراضيًا.

## 4. العيوب المؤكدة مرتبة بالأولوية

### P0 — مانعة للدمج والإصدار

1. **فشل TypeScript في fixture تشخيص OCR.** قيمة `diagnosticCode` في جدول `it.each` تُستنتج `string` بدل union. الإصلاح الصحيح هو تثبيت الجدول بـ`as const`/`satisfies` لنوع التشخيص، لا إضعاف النوع.
2. **تجاوز حد الملف التنفيذي.** `processing-job-executor.ts` وصل 518 سطرًا. استخرج تحويل التشخيص ومسار retry/fail إلى adapter مستقل مختبر؛ لا ترفع baseline.
3. **تجاوز ميزانية JavaScript بـ1.6 KiB gzip.** لا ترفع الميزانية. ابدأ بسجل الأيقونات المركزي الذي يحمل مجموعة Lucide مشتركة، وانقل أيقونات/واجهات المحررات إلى chunks الخاصة بالمسارات، وأزل CSS/JS المكرر. استهدف ≤164 KiB لإعادة هامش آمن.

### P1 — أخطاء صحة بيانات/فقد عمل

4. **فقد مسودة مناطق PDF عند العودة للرئيسية.** الحارس الحالي يعرف تعديلات مراجعة الطبقات فقط؛ `pdfRegionsDirty` يُستخدم عند الانتقال بين الصفحات/اختيار طبقة أخرى، ولا يدخل حارس التنقل العام أو `beforeunload`. أُعيد إنتاجه فعليًا.
5. **منطقة PDF صفرية غير مرئية.** `x=100` قيمة صحيحة للنموذج، ثم `Math.min(width, 100-x)` ينتج صفرًا ويُرسل. يلزم invariant مشترك في العميل والعقد والخادم: إحداثيات ضمن `[0,1)` وأبعاد موجبة و`x+width<=1` و`y+height<=1`، مع فشل واضح بدل القص الصامت.

### P2 — UX، إتاحة وأداء

6. **رصيف الطبقات يضع كل الصفحات تحت عنوان ثابت «الصفحة 001».** يجب تمرير الصفحة النشطة وتجميع الصفوف حسب `pageNumber`، أو إظهار الحالية فقط مع وضع «كل الصفحات».
7. **الهاتف يرسم `layers.map` بلا حد.** هذا خطر مباشر مع `maxPdfTextItems=100,000`. استخدم قائمة افتراضية مشتركة، نافذة DOM ≤60 صفًا، وترقيم/بحث على مستوى كل الصفحات.
8. **سبب تعطيل الأداة غير متاح على سطح المكتب.** `disabled + title` لا يكفي للمس/لوحة المفاتيح/قارئات الشاشة. وحّد سطح المكتب مع نمط الهاتف: `aria-disabled`، منع التنفيذ، `aria-describedby` ونص مرئي أو popover قابل للتركيز.
9. **المساحة الرسومية للصورة تحمل `role="application"` و`tabIndex=0` بلا أوامر لوحة مفاتيح.** إما تنفيذ أسهم/مسافة وتعليمات كاملة، أو تغييرها إلى `region/img` وترك الإدخال بنموذج الإحداثيات.
10. **معرف ضربة الصورة يستخدم `Date.now()` بينما إدخال لوحة المفاتيح يستخدم UUID.** استخدم `crypto.randomUUID()` في المسارين لمنع التصادم.
11. **ترتيب مناطق الاستثناء غير متسق.** الاستثناءات تحصل على order لكن تُستبعد عند حساب التالي؛ قد تتكرر القيم عند تغيير الدلالة. اجعل order=`null` للاستثناء أو أعد تطبيع ترتيب القراءة بعد كل تغيير.
12. **مفاتيح React لمعاينة الأسماء مبنية على الاسم.** الأسماء المكررة تولد مفاتيح مكررة؛ استخدم `layer.id`.
13. **`ProcessingMode` ما زال يتضمن `automatic` بعد حذف الخيار من الواجهة.** افصل «معالجة الرفع» عن «نمط التصحيح»، ثم احذف الفروع الميتة بعد تحديث العقد والاختبارات.
14. **تجربة تحميل capabilities ناقصة.** الفشل fail-closed جيد، لكن حالة `loading` لا تعرض skeleton/حالة واضحة. عطّل إنشاء/رفع المشروع حتى الجاهزية، واعرض إعادة المحاولة وcorrelation ID عند الخطأ.

### P2 — قابلية الاختبار والملاحظة

15. **نجاح E2E لا يغطي الأدوات الحرجة.** الاختبارات الحالية تثبت الرفع والجاهزية وإتاحة أساسية، لكنها لا تختبر المناطق، المسودات، grouping الطبقات، split/merge، undo/redo، استبدال المصدر أو الفشل/إعادة المحاولة.
16. **تشخيص OCR آمن لكنه محصور في السجل.** خزّن summary محدودًا بلا نص مصدر في محاولة المهمة/واجهة الإدارة، واربطه بـcorrelation ID وإجراء retry. لا تسجل تشخيصًا فارغًا للأخطاء غير المتعلقة بـOCR.
17. **وضع التطوير المتطاير يربك QA.** `tsx watch` مع repositories داخل الذاكرة قد يعيد العملية ويفقد الجلسات/المشاريع. وفر `dev:durable` افتراضيًا لـPostgreSQL/Redis/S3 محلي، وأظهر شارة «ذاكرة مؤقتة» عند الوضع الخفيف.

## 6. تحسين تجربة مساحة العمل

### مربع رفع الصور وPDF

- اجعله state machine مرئية: `تحقق محلي → رفع → معالجة → فحص → جاهز/يحتاج مراجعة`، مع نسبة حقيقية لكل مرحلة.
- اعرض الحجم والأنواع والحدود القادمة من `/v1/capabilities`، وافحص signature/MIME قبل إنشاء المشروع، لكن أبقِ الخادم سلطة التحقق.
- وفر إلغاءً حقيقيًا، إعادة محاولة idempotent، واستكمالًا أو إعادة رفع دون إنشاء مشاريع يتيمة.
- عند الاستبدال اعرض النسخة الحالية والجديدة وتأثيرها على مسودات الإرشاد؛ اربطها بحارس التنقل.
- لا تضف رفعًا متعدد الملفات الآن؛ المنتج والعقود مصممان لمصدر واحد، وسيزيد ذلك عبء العمليات بلا حاجة مثبتة.

### الطبقات

- طبقات PDF حسب الصفحة مع sticky headers، فتح الصفحة الحالية تلقائيًا، ومرشح «الحالية/كل الصفحات».
- virtualization موحد للهاتف وسطح المكتب، مع البحث والتحديد خارج النافذة دون فقد الحالة.
- تمييز الرؤية والقفل والتحذير والنوع بأيقونات غير متشابهة، وأهداف لمس ≥44px، ودعم `Alt+↑/↓` مع إعلان حي للنتيجة.
- احتفظ بالحد 15 للصورة، واعرض عدادًا مسبقًا وتأثير merge؛ لا تعرض «بلا حد» للـPDF لأن هناك حدًا تشغيليًا 100,000 عنصر.

### الصفحات

- أضف شريط thumbnails كسولًا للـPDF، إدخال رقم صفحة، وعدّاد طبقات/تحذيرات لكل صفحة.
- اجلب thumbnail عند الاقتراب فقط، وألغِ الطلبات عند التنقل السريع.
- اجعل الانتقال صفحة/طبقة/بحث يمر عبر حارس مسودة واحد، مع خيارات «تطبيق»، «حفظ مسودة»، «تجاهل»، «إلغاء».

### الأيقونات والأعمدة

- استبدل رمز `refresh` المشترك لـredo/source versions/turntable برموز Redo/History/Rotate3D مميزة، وراجع اتجاه الأسهم في RTL.
- حافظ على label نصي للأوامر المهمة؛ tooltip وحده ليس بديلًا.
- اجعل الأعمدة الثلاثة (أدوات، معاينة، طبقات) قابلة للطي والتغيير بلوحة المفاتيح مع min/max وحفظ القياسات لكل مستخدم، وأضف preset «تركيز المعاينة» و«مراجعة الطبقات» بدل مزيد من الأعمدة.

## 7. الإنتاج والأمن والتشغيل

الوضع المحلي الجيد لا يمنح Go. يجب تنفيذ الترتيب الموجود في `docs/EXTERNAL_GATE_INPUTS.md` على نفس SHA:

1. إغلاق P0 ودمج المرشح ومراجعة التغيير.
2. Hosted CI كامل، QA image، durable PostgreSQL/S3، E2E والمسوح الأمنية.
3. نشر صور runtime/web موقعة مرتبطة digest مع SBOM/provenance.
4. Staging بنفس digests مع Character وregional OCR وlive billing معطلة.
5. اتصال مُدار PostgreSQL 17/Redis TLS/S3 مشفر/SMTP، migrations المتزامنة واختبارات durable.
6. استعادة PostgreSQL+object store معًا وإثبات RPO≤15 دقيقة وRTO≤4 ساعات.
7. fault injection وحمل/ذاكرة وتمرير queues إلى صفر، تحقق تنبيهات وrollback.
8. بوابات Character الخاصة: egress allowlist، timeout/retry/rate limit/SHA/cleanup/leases ثم Golden وموافقات product/legal وcanary تدريجي.

## 8. خطة التنفيذ المتسلسلة

### المرحلة 0 — استعادة خط الأساس (1–2 يوم)

- أصلح fixture النوعي، استخرج diagnostics/retry من executor، وخفّض الحزمة تحت 164 KiB gzip.
- أصلح المنطقة الصفرية وحارس مسودات PDF/الصورة وتجميع الطبقات حسب الصفحة.
- **معيار القبول:** typecheck/maintainability/bundle كلها خضراء، ولا فقد مسودة في back/mode/source/page/beforeunload، ولا يقبل العميل أو API منطقة صفرية.

### المرحلة 1 — صحة المحررات والإتاحة (3–5 أيام)

- وحّد أسباب التعطيل، أصلح role/keyboard/UUID/order/keys، وافصل `automatic` عن correction mode.
- أضف unit tests للمحررين وWorkspace واختبارات عقد تحقق المنطقة.
- **معيار القبول:** تغطية الملفات الحرجة ≥80% statements و≥70% branches، وaxe بلا critical/serious في workspace.

### المرحلة 2 — الطبقات والصفحات والأداء (5–8 أيام)

- قائمة افتراضية مشتركة، grouping وفهرسة الصفحات، thumbnails كسولة، تخطيط أعمدة محفوظ.
- benchmark لملف synthetic قريب من 100,000 عنصر.
- **معيار القبول:** ≤60 صف DOM، تفاعل تحديد/بحث p95≤100ms على الجهاز المرجعي، لا long task>200ms عند فتح اللوحة، ولا نمو ذاكرة مستمر بعد 20 تبديل صفحة.

### المرحلة 3 — الرفع والتشخيص وجودة الاختبار (3–5 أيام)

- state machine للرفع، تشخيص bounded مستمر، correlation IDs، retry مصنف، `dev:durable`.
- وسّع E2E بالمناطق والمسودات والطبقات وsplit/merge/history/source replacement وحالات الفشل.
- **معيار القبول:** 20+ سيناريو E2E ذي قيمة (لا تكرار شكلي)، نجاح retry دون مشروع/مهمة يتيمة، وسجل بلا نصوص مصادر أو أسرار.

### المرحلة 4 — أدلة الإنتاج الخارجية (تعتمد على المالك/المزود؛ 1–2 أسبوع عادة)

- نفذ خطوات staging/recovery/load/fault/rollback ثم بوابات OCR/Character المستقلة.
- **معيار القبول:** تقارير موقعة مرتبطة بنفس SHA/digests، صفر High/Critical غير محلول، موافقات تشغيل/خصوصية/قانون/منتج موثقة، وخطة kill switch مجربة.

## 10. قرار الحذف والإضافة

- **لا حذف فوري:** لا يوجد dead code مؤكد، والعقود الحالية تُلزم الحفاظ على المسارات. حذف أي أداة يجب أن يبدأ بقرار منتج وtelemetry واستهلاك، ثم deprecation/versioning.
- **إضافة ضرورية:** حارس مسودة موحد، validator هندسي مشترك، virtualized page-aware layers، page navigator، diagnostics summary، وdev durable profile.
- **تبسيط مطلوب:** إزالة `automatic` من محررات التصحيح بعد فصل المفهوم، وتقسيم executor، وتقليل سجل الأيقونات المحمل عالميًا.

## 11. تعريف الاكتمال

لا تعتبر الجولة مكتملة إلا إذا نجح `npm run quality` كاملًا، وE2E الموسع على Desktop/Pixel 7، وقياسات 100,000 طبقة، وفحص الإتاحة، ولم يعد هناك فقد لمسودات أو عمليات صامتة، ثم مرّ المرشح نفسه بلا تغيير عبر الأدلة المستضافة وبيئة staging والاسترداد والحمل والrollback. حتى ذلك الوقت تبقى الحالة الصحيحة: **Production No-Go**.
