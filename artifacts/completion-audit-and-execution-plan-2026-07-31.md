# تدقيق استكمال MotionPrep وخطة التنفيذ

التاريخ: 2026-07-31

الفرع: `codex/production-readiness`

خط الأساس: `17b7dd25dd0e53c35ec14a731c9e61ad69c1082c`

القرار: **مرشح قوي محليًا، لكنه No-Go للإطلاق العام حتى إغلاق أدلة OCR والمزوّد والاستعادة وAdobe.**

## الملخص التنفيذي

- سجل الأدوات يحتوي 19 أداة فريدة، وكلها `ready`؛ لا توجد أداة مسجلة `planned` أو زر مقصود بلا مسار تنفيذ.
- لم تُثبت جولة الاستخدام الفعلي عطلًا مرئيًا متكررًا. نجحت رحلة الصورة وPDF والتصدير والاستبدال المؤكد، إضافة إلى سطح المكتب والهاتف ولوحة المفاتيح.
- أُغلقت مخاطر P0/P1 القابلة للإصلاح داخل المستودع: الثقة ببيانات إكمال الرفع، سباق حالة المشروع، أحداث Stripe الخارجة عن الترتيب، إيقاف العمال، جدولة الاحتفاظ، إعادة المحاولة الإدارية، وصدق خيارات التصدير.
- لا تزال موافقة الإنتاج محجوبة لأسباب خارجية أو تجريبية محددة، وليست بسبب أداة واجهة ناقصة.

## ما اكتمل في هذه الدورة

| المجال | التنفيذ | دليل القبول |
|---|---|---|
| رفع الملفات | الخادم يفحص object المخزن والحجم والنوع وSHA-256 والتشفير قبل `ready`، ولا يقبل بيانات العميل كحقيقة | اختبارات missing/mismatch/replay/ownership وMinIO فعلي |
| استبدال المصدر | يتطلب `replaceSourceVersion=true` عند وجود مصدر حالي | API يعيد `409 SOURCE_REPLACEMENT_CONFIRMATION_REQUIRED` دون التأكيد، والواجهة تعرض حوارًا واضحًا |
| حالة المشروع | ربط الحالة بالمصدر والمهمة الحالية، وإنهاء مشروط بـjob/source، ومنع مهمة ثانية من الاستيلاء على الحجز | PostgreSQL حقيقي يثبت single-owner ورفض النتيجة القديمة |
| العمال | إيقاف claims عند SIGTERM، drain محدود، وإعادة lease غير المنشور للطابور دون استهلاك محاولة | اختبارات drain/requeue، وCompose يمنح مهلة أكبر من مهلة drain |
| Stripe | حفظ `occurredAt` وآخر event ID وتحديث اشتراك ذريًا فقط للحدث الأحدث | duplicate/out-of-order/concurrent integration |
| الاحتفاظ | batches ومعاملة، advisory lock، scheduler، حالة تشغيل دائمة، metrics وتنبيه تأخر | اختبارات نجاح/فشل/تزامن، وبيانات `maintenance_status` |
| الإدارة | إعادة مهمة فاشلة فقط للمدير، بسبب لا يقل عن 10 أحرف، مع CAS وحد المحاولات وaudit | اختبارات RBAC والحالات غير الصالحة والنجاح |
| التصدير | إزالة الخيارات الزخرفية؛ scale/profile/naming تدخل الطلب الفعلي وتظهر بصيغة صادقة حسب format | اختبارات العقد والخدمة والواجهة |
| الطبقات | سحب فعلي، أزرار ترتيب، `Alt+Arrow`، تنقل `Arrow/Home/End` ونافذة 32 طبقة | اختبارات منطقية وجولة لوحة مفاتيح فعلية |
| PDF | حدود مشتركة للواجهة والعقد: 30 MiB، 250 صفحة، 100,000 عنصر نصي | اختبار العقد ونص المساعدة؛ محرك OCR بقي مطابقًا لبصمة holdout المفتوحة |
| الإطلاق | إعادة `quality` وaudit وtopology على SHA الإصدار قبل النشر، مع بيئة `production-release` محمية | verifier ثابت، وworkflow يمنع `publish` قبل `verify-source` |
| الذاكرة والتخزين | تنزيل artifacts متدفق مع backpressure وإلغاء عند قطع العميل؛ قراءات المعالجة محدودة بالحجم المسجل؛ SHA-256 يتحقق أثناء البث | اختبارات التخزين المحلي وS3 والخدمة والمسار، بما فيها الإلغاء والفساد وتجاوز الحد |
| التغطية | إضافة اختبارات البث وإلغاء S3 وفساد Raster ورفض أحجام الكتابة المتناقضة، ورفع baseline الواجهة | API: 153 اختبارًا؛ حدود الواجهة أصبحت 47/45/37/49 |

## الأدوات والوظائف غير المكتملة

### P0 — تمنع إعلان Go

1. **OCR المستقل:** holdout generation 6 عند CER ‏27.02% مقابل الهدف ≤25%. النطاق الآمن هو الوثائق العربية المطبوعة مع مراجعة بشرية؛ المخطوطات والجداول المتدهورة ليست ضمن ادعاء موثوق.
2. **مزوّد الإنتاج:** لا يوجد بعد إثبات محفوظ من bucket حقيقي لسياسات TLS/versioning/encryption/lifecycle/least privilege بهوية workload.
3. **Staging وrollback:** لم يُنشر هذا المرشح إلى staging بصور digest موقعة ثم يُرجع إلى digest سابق دون build.
4. **التعافي:** manifest المثال يثبت صحة الأداة، لكنه ليس drill مزوّدًا وموقعًا يثبت RPO ≤15 دقيقة وRTO ≤4 ساعات.
5. **Adobe:** ملفات PSD التجريبية موجودة، لكن لا يوجد اعتماد بصري في نسخ Photoshop/After Effects المرخصة المستهدفة.

### P1 — تشغيل قبل التوسع التجاري

1. اختيار مزوّد واحد وكتابة IaC خاص به بدل بنية سحابية افتراضية متعددة المنصات.
2. توصيل Prometheus/Alertmanager بمالك فعلي وإجراء اختبار وصول تنبيه retention/queue/worker.
3. تفعيل branch/tag rulesets واشتراط `quality` وCodeQL وبيئة الإصدار المحمية في GitHub.
4. تنفيذ load test بأحجام PDF ممثلة قبل زيادة `DOCUMENT_PROCESSING_CONCURRENCY`.

### P2 — تحسينات لاحقة لا تمنع الإصدار المحدود

1. **مكتمل:** تنزيلات S3 والتصدير تستخدم streaming/backpressure مع فحص تدريجي للبصمة وإلغاء upstream عند قطع العميل. بقيت مدخلات PDF/Sharp محدودة ومجمعة لأن المحركات تتطلب random access.
2. **بدأ التنفيذ:** رُفع baseline تغطية الواجهة لمنع التراجع؛ يستمر توسيع قائمة الملفات واختبارات التفاعل تدريجيًا.
3. دمج CSS تدريجيًا حسب ownership بدل إعادة كتابة شاملة.
4. تحديث dependencies على دفعات صغيرة؛ كل major في PR مستقل مع quality وE2E وtopology.
5. إنشاء visual regression ثابت لمسارات RTL والهاتف ولوحة الطبقات.

## بوابة التسليم

لا يتحول القرار إلى Go إلا مع: جميع P0 خضراء، لا ثغرة High/Critical، quality وE2E وPostgreSQL/S3 integration وproduction topology ناجحة على SHA نفسه، صور digest موقعة، rollback مجرب، تنبيهات تصل إلى مالك، ووثيقة readiness محدثة بالأدلة لا بالافتراضات.
