# تنفيذ مجلدات صفحات PDF — 2026-08-13

## النتيجة

تم تنفيذ اقتراح مجلد الصفحة كبنية بيانات محفوظة وواجهة متطابقة، لا كتجميع بصري فقط. كل صفحة PDF جديدة تحصل على مجموعة جذرية باسم تقني ثابت مثل `+page_001`. الخلفية والنصوص أبناء لها، وتبقى المجموعات الدلالية (عنوان/موضوع) متداخلة أسفل جذر الصفحة.

## عقد السلوك

- مجموعة الصفحة والمجموعات الدلالية عناصر بنيوية لا تدخل في عدّاد الطبقات.
- العدّاد المشترك يعرض `طبقات الصفحة الحالية / الإجمالي`، مع عدد الصفحات منفصلًا.
- المستندات القديمة بلا مجموعات صفحة تحصل على مجلدات افتراضية وقت العرض فقط، دون هجرة مدمرة.
- اختيار صفحة أو نتيجة بحث في صفحة أخرى يمر عبر حارس المسودة غير المحفوظة.
- البحث في وضع PDF يشمل محتوى كل الصفحات ويكشف المجلد المطابق.
- النقل والتحديد المتعدد لا يعبران الصفحة أو المجموعة الأم، وتوحيد الأسماء في PDF يكون داخل الصفحة.
- regional OCR يرث جذر الصفحة؛ ومجموعة guidance الدلالية تصبح ابنًا لجذر الصفحة.
- تصدير PSD الكامل ينشئ مجلد صفحة واحدًا فقط ويحافظ على التعشيق الدلالي.
- لم تتغير مسارات ملفات ZIP، ولم يتغير سقف PDF البالغ 30 MiB.

## مناطق التغيير

- التسمية/الكشف المركزي: `packages/presets/src/index.ts`.
- توليد المستند: `packages/document-processing/src/pdf-source.ts`.
- OCR وguidance: `apps/api/src/processing/pdf-region-ocr.ts` و`packages/guidance/src/index.ts`.
- PSD: `packages/export-adapters/src/pdf-psd.ts`.
- نموذج الويب/selectors: `apps/web/src/types.ts`، `workspaceDocument.ts`، `layerPageScope.ts`، `layerDockSelectors.ts`.
- الواجهة المشتركة: `PdfPageLayerTree.tsx`، `LayerDock.tsx`، `WorkspaceMobileSheet.tsx`، وCSS مساحة العمل.
- حارس الانتقال: `Workspace.tsx` مع تمريره إلى desktop/mobile.
- سلامة الترتيب: `layerReviewState.ts`.

## التوافق

- بقي `schemaVersion` عند `1.0` لأن العقد يدعم `kind: group` و`parentId` بالفعل.
- المستندات الجديدة تحفظ الجذر الحقيقي؛ المستندات القديمة تظل قابلة للفتح والبحث والعد والتصدير عبر مجلد افتراضي.
- single-page PSD بقي بلا غلاف إضافي حفاظًا على المستهلكين الحاليين.
- manifest يحفظ عقد المجموعة وعلاقات `parentId` تلقائيًا، دون تغيير أرشيف ZIP.

## ملاحظات وحدود معروفة

- لم تُغيّر هذه الدفعة مسارات ZIP عمدًا لتجنب كسر التوافق.
- لا توجد virtualization للشجرة؛ البحث لا يخفي نتائج بنافذة ثابتة. يمكن قياس الحاجة إليها لاحقًا على مستندات ضخمة فعلية.
- اختبار Playwright يتطلب بيئة stack/fixture مصادق عليها؛ غطت اختبارات React التفاعل المكتبي المباشر، بينما يلزم dogfood بصري منفصل على بيئة التشغيل.

## جولة ما بعد المراجعة

- أصبح تنقل محرر PDF يستدعي مسار الانتقال المحروس فقط؛ لا تتغير الصفحة أو الأبعاد أو الطبقة المحددة قبل قبول الحارس.
- أصبح اختيار البداية والتعافي من selection مفقود يتجاهلان مجموعة الصفحة البنيوية، ويفضّلان النص ثم المحتوى ثم خلفية الصفحة.
- أصبحت مجموعة الصفحة مستبعدة من قائمة مراجعة التصدير والعداد والمعاينة والمحرر، مع بقائها محفوظة داخل payload ووثيقة الطبقات.
- أضيف دفاع إضافي يمنع حفظ أي تعديل عارض على `kind: group`.
- التقييم البصري الحي لملف PDF لم يحصل على حكم PASS: تعذر إكماله لأن بيئة API الحية لم تكن متاحة. نتائج الوحدة/التكامل والبناء أدلة آلية فقط ولا تُقدَّم على أنها اعتماد بصري.

## المراجعة البصرية المعزولة — الجولة الثانية

- أُنشئت بيئة تحقق مؤقتة غير إنتاجية تستورد المكوّنين الحقيقيين `PdfPageLayerTree` و`WorkspaceMobileSheet` مع CSS المشروع، وبيانات PDF حتمية من صفحتين تشمل جذري صفحة، مجموعتين دلاليتين، خلفيات، وطبقات نص عربية في RTL.
- نجح فحص Playwright البصري للحالتين المكتبية والهاتفية `2/2`، واعتمدت واجهة الشجرة بصريًا بحكم **PASS** عند 1440 و1024 و768 و375 بكسل من حيث التدرج، الإفصاح، العدادات، البحث العابر للصفحات، التركيز، واتجاه RTL.
- كشف الفحص تعارضًا بين مقبض الورقة وقاعدة هدف اللمس العام `44px`. أُبقي هدف النقر الآمن بحجم 44 بكسل، ونُقلت العلامة المرئية إلى pseudo-element بارتفاع 4 بكسل، فأصبح المقبض المرئي `48×4` دون إضعاف قابلية الوصول.
- أصبح مجلد الصفحة النشطة يعرض وسمًا نصيًا صريحًا «الصفحة الحالية» على الهاتف، مع بقاء `aria-current="page"` والتسمية الوصفية القائمة.
- رُفعت قراءة اسم طبقة الهاتف إلى 10 بكسل داخل الصف المرن، وأضيف `title` والاسم الميسّر الكامل حتى يبقى النص الكامل متاحًا عند الاقتطاع على عرض 375 بكسل.
- لقطة الاعتماد النهائية: `artifacts/pdf-page-folder-visual-evaluation-2026-08-13/mobile-tree-375-final.png`.
- هذا الحكم PASS خاص بسلامة واجهة المكوّن المعزولة بالبيانات الواقعية الحتمية؛ قيد عدم توفر مسار API الحي المذكور أعلاه ما يزال موثقًا ولا يُعاد توصيفه كاختبار backend شامل.
- تحقق الجولة النهائية: Playwright للـharness `2/2`، واختبار React المركز `4/4`، وtypecheck للويب وESLint للملفات المعدلة وStylelint الكامل وبناء production ومدقق الصيانة كلها ناجحة. حُذفت بيئة الـharness المؤقتة وأُوقف خادمها بعد حفظ الأدلة.
